## Router Type

Not applicable — this project does not use Next.js, Pages Router, or App Router.

Routing is provided by `@loom-js/core`'s built-in router — one layered pipeline per window (raw location activity → match transform → route activity), with the router instance keyed by the provider window (`WeakMap` in `packages/core/src/router.ts`): the browser gets one router for the page's lifetime, each server render gets its own.

| API                        | File                                                                                                                                                                  |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `createRoutes(config)`     | Registers the route table & returns the routes component. DOM-free at call time — module scope is safe off-browser; a repeat call replaces the table (last call wins) |
| `routeEffect(callback)`    | Subscribes to route changes (matched-route layer; needs a route table)                                                                                                |
| `route(event, opts)`       | Click handler for SPA navigation; wraps `window.history.pushState`                                                                                                    |
| `redirect(href)`           | Programmatic navigation via `replaceState`                                                                                                                            |
| `watchRoute(handler)`      | Runs a callback any time the route updates                                                                                                                            |
| `locationEffect(callback)` | Zero-config effect over the raw `Location` (layer 1; no route table needed)                                                                                           |
| `watchLocation(handler)`   | Zero-config watcher over the raw `Location`; returns an unsubscriber                                                                                                  |
| Route config               | `apps/loom/src/app/pages/routes.ts`                                                                                                                                   |

The legacy `routing.ts` module (`router`, `onRoute`, `onRouteUpdate`) was removed pre-1.0 without a deprecation bridge — the replacements are `locationEffect`, `route`, and `watchLocation` respectively. Those names no longer exist in the package; do not reference them.

## Notes

### Component model

- Component unit = one `component()` call or one `simple()` call — both return a callable producing a `ContextFunction`.
- `component()` holds its own template context (memoized across renders); `simple()` wraps a pass-through render function (returns `ContextFunction`(s) from other components, no template of its own). Declare pass-throughs via `simple<Props>(render)` — never as bare `SimpleComponent`-annotated functions: the factory guarantees the render function a props object (`{}` on propless calls), so implementations destructure without `= {}` defaults.
- Props are conditionally required (`core-types-cleanup`): `Component<Props>`/`SimpleComponent<Props>` accept propless calls only when `Props` has no required members. `component()`/`simple()` handle the runtime default internally.
- Templates use tagged-template literals with a single top-level element.
- Components compose in templates as elements (`<${Component} prop=${value}>…</>`); children markup becomes the `children` prop, and `slot="name"`-labelled top-level children become named regions on the `slots` prop (`${slots?.name}` in the receiving template). Labels must be static quoted strings; the functional form is the identical call (`Component({ slots: { name: … }, children: … })`).
- Spread props: `...${object}` in a component element's attribute region spreads the object's entries as props with object-literal semantics (authored order, last-wins duplicates; nullish/primitive values are a no-op) — identical to `Component({ ...object })`. A `slot` key via spread is an ordinary prop, never a label, and markup `children`/`slots` win over spread-supplied ones.
- Core element components (`src/elements/`): `RouteLink` (self-wired SPA routing), `Svg`, `Picture`, and `el(tagName)` (a plain tag as a memoized component value — for `is=` props, render callbacks, and props transformers). Convention: every top-level `component()`/factory definition in a shakeable core module carries a `/* @__PURE__ */` annotation (the build preserves them — do not re-add `removeComments` to the package tsconfig or drop terser's `preserve_annotations`).
- **Authoring convention (markup-first):** element syntax is the primary authoring surface — compose in markup; the functional call is the sanctioned escape hatch for genuine value positions (effect returns, `.map` items, `is=` props, props transformers), with `el(tagName)` covering plain tags there. The retired `@loom-js/tags` wrapper layer is NOT the pattern for new code. Conversion patterns from `element-syntax-conversion`: components that own structure become templates; pure delegators (root supplied by `is`) stay functional over `el()` roots; components consumed as children-array items must not be component-tag-rooted templates (fragment roots stringify via the array-reconciliation limitation); regions interpolate in templates, never as children-array items; a style value that resolves to nothing must be omitted, not passed (the `style=` binding renders the template sentinel for empty values).
- Lifecycle hooks (`onCreated`, `onRendered`, `onMounted`, `onUnmounted`, `onBeforeRender`) are provided via props.

### Reactivity

- `activity(initialValue)` — pub/sub reactive primitive; `.effect()`, `.update()`, `.value()`, `.reset()`, `.watch()`.
- Activity effects run immediately on first render and on every subsequent `update()`.
- Effects must return a `ContextFunction` (the result of calling a component).

### External data boundaries (DIP)

- **S3 log writes** — abstraction boundary: `LogStore` interface in `services/utils/log-store.ts`; `S3LogStore` implementation in `services/utils/s3-log-store.ts`. Handlers accept `LogStore` as an injected parameter.
- **Contentful reads** — go through `contentfulRequest` (in `apps/loom/src/app/logic/providers/contentful/lib/contentful-request.ts`) which wraps `graphQlRequest` from `@loom-js/utils`. Not direct SDK usage.
- `__API_URL__` and `__CTF_IS_PREVIEW__` are esbuild `define` values — treat as build-time constants, not runtime dependencies.

### Framework DOM APIs

DOM primitives are the domain of this framework — using them heavily inside `packages/core/src/` is **not** a DIP violation. However, since `add-server-rendering`, core code resolves them through the provider seam in `src/lib/dom.ts` — `getWindow()`, `getDocument()`, `withWindow()` — instead of bare globals (`document.*`, `window.*`, bare `instanceof HTMLElement`), so the same render path runs against an injected DOM (linkedom) on a server. New core code must do the same. Two subtleties: nothing may touch the DOM at **module load** (lazy-init instead — see the window-keyed lazy router construction in `router.ts`), and cached template fragments are re-cloned via `getDocument().importNode(...)`, never `cloneNode`, so custom elements upgrade in whichever document is rendering.

### Dependency security conventions

- pnpm `overrides` live in `pnpm-workspace.yaml`; each must be annotated inline with the GHSA id(s) it addresses, the parent that pins the vulnerable version, and its removal condition. No blanket overrides.
- Advisories deliberately left open are recorded in `ACCEPTED-ADVISORIES.md` at the repo root with a reason (no patch / unacceptable break / not reachable). An advisory absent from that file is untriaged, not accepted.
- `typescript` stays on 6.x until `@rollup/plugin-typescript` can load TS 7.
