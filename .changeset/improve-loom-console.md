Improve the framework console (`loomConsole` / `loom.console`) on three fronts. **Warnings and errors always surface**: `warn`/`error` bypass the debug gate entirely — attr-misuse warnings and the `hydrate`/`renderToString` `maxWait` expiry warnings now reach the console in development and production alike, with no `setDebug` opt-in (apps that relied on debug-off silence will newly see genuine warnings — intended). **Call-site attribution is fixed**: method access returns a native console method bound to the console (or a shared no-op when the gate is closed) instead of a wrapper closure, so DevTools attributes each message to the framework call site that logged it, not to `loom-console.ts`; the gate is read at property-access time, so don't cache method references. **Debug narration is tamed**: the per-value "should update" log folds into a collapsed `loom (Updating…)` group per update cycle, and the double-gating `console` scope is gone — each debug call site is gated once, by its own scope. `ConfigDebugAllowable` shrinks to `activity`, `creation`, `mutations`, `updates` (the `console`, `warn`, and `error` keys are removed — a type-level break for `setDebug`/`debugScope` callers passing them; runtime tolerates unknown keys).
